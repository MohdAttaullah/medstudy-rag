## Purpose

Ensure an M7 grounded draft is **not shown as a verified answer unless every material factual claim
is sufficiently supported by the authoritative retrieved EvidenceSet and all citation and provenance
checks pass**. M8 is the final answer-safety layer before the full Ask experience in M9.

The pipeline becomes: question → M5 retrieval → M6 reranking → EvidenceSet → M7 sufficiency gate →
SUFFICIENT → M7 grounded draft → M8 claim verification → PASS / REGENERATE_ONCE / ABSTAIN. An
`INSUFFICIENT` or policy-blocking `CONFLICTING` gate remains an abstention; M8 must not invoke
generation to overcome missing evidence. A generated draft is untrusted until verified, the M7
`UNVERIFIED_AWAITING_CLAIM_VERIFICATION` state must stay meaningful, and pretrained knowledge is
still not evidence.

## Claim extraction and materiality

Create a typed claim-extraction stage decomposing the draft into reviewable atomic factual claims,
so that a compound sentence becomes separate claims, without fragmenting stylistic or connective
language. Claims need stable request-scoped ids and should preserve their location in the draft,
capturing approximately claim id, text, span, materiality/type and cited EvidenceBlock ids, using
repository conventions.

Verify substantive factual medical claims — diagnostic facts, mechanisms, drug names, dosages,
frequencies, contraindications, side effects, numeric values, percentages, lab values, anatomical
relationships, definitions, formula interpretations, table-derived facts and question-bank answer
assertions — without wasting verifier capacity on connectives, and without classifying a medical
statement as non-material merely because it is inconvenient to verify. This remains an educational
product, not patient-specific diagnosis or treatment.

## Citation and deterministic verification

Every material claim maps to one or more EvidenceBlock ids that exist in the exact M6 EvidenceSet
supplied to M7. Deterministically reject an unknown, cross-request, cross-tenant, absent or
malformed citation id and a missing required citation, and never let a verifier model invent
replacement ids.

Before any semantic verifier is consulted, check that citation ids exist, that blocks belong to the
request, that tenant/corpus/version alignment holds, that source provenance, page identifiers and
artifacts resolve, that source offsets are internally valid and that the claim has required citation
coverage. A deterministic failure is a hard verification failure; do not ask an LLM whether a
nonexistent citation is acceptable.

## Semantic verification

After deterministic validation, determine whether each claim is supported by its cited blocks,
behind a provider-neutral abstraction distinguishing supported, unsupported, contradicted,
insufficient-evidence and unverifiable, without reducing these to a fake percentage confidence.

Isolate any model behind a verifier abstraction rather than embedding vendor SDK calls in domain
code. The verifier receives only the claim, its approved cited blocks, the verification policy and a
structured output schema — no unrestricted corpus access, no web search, and no supplementing from
pretrained knowledge. It must return a strict schema capturing claim id, verdict, supporting and
contradicting evidence ids and a reason code; free-form prose is not the machine decision, and
malformed output, unknown ids and attempts to introduce unsupplied evidence are rejected.

Support a verifier model or provider distinct from the generator where practical, to reduce
correlated failure. Do not require two paid accounts to make M8 testable, keep deterministic fake
verifiers viable for CI, allow same-provider verification where necessary, and document the
independence limitation explicitly when the same model is used. Never rely on asking the generator
whether its own previous answer was correct.

## Contradiction, authority and structured evidence

M7 documents that its conflict detector over-triggers conservatively and can miss prose-level
contradictions; M8 must improve that boundary. Check whether a claim contradicts its cited evidence,
whether it is supported by one source and contradicted by another retained block, and whether two
authoritative blocks materially disagree. Reranker order must not determine truth and the highest
CrossEncoder logit must not automatically win. Source authority remains relevant, but conflicting
authoritative medical sources must remain visible.

Preserve source metadata throughout. Question-bank answers remain assessment content: a claim
supported only by a low-authority question-bank answer must not silently become authoritative
medical fact when stronger contradictory reference evidence exists. Document how authority affects
verification without converting it into an arbitrary numeric confidence.

Verify table-derived claims against the canonical table artifact rather than flattened prose alone,
preserving row identity, header identity, footnotes, the artifact and source provenance, and fail
closed when structure is missing rather than letting the verifier reconstruct cells. Verify formula
claims against the exact source expression, definitions and associated explanation, never letting a
verifier "correct" the source, and return insufficient or unverifiable when the definitions needed
are absent. Preserve M7's figure boundary: generated captions are not authoritative evidence, M3
structural labels are not visual content, and a claim requiring the original figure abstains unless
an explicit architecture decision introduces approved original-artifact vision verification.

Give special attention to dosages, percentages, lab values, units, ranges, frequencies, durations,
ratios and formula outputs, requiring exact or appropriately normalized support — 5 mg is not
50 mg and units are not silently dropped — with dedicated tests. Preserve medically meaningful
qualifiers such as not, may, must, usually, rarely, contraindicated, recommended, associated with,
only when and except: a claim reversing negation must fail, and a draft must not strengthen "may be
associated with" into "causes" unless the evidence supports the stronger statement. Add targeted
tests. A material claim is not verified merely because one phrase overlaps with evidence; verify the
whole atomic proposition, which atomic extraction should help enforce.

## Final policy, repair and output

Implement a typed policy producing PASS when all required material claims are supported and
deterministic checks succeed, REGENERATE_ONCE when a limited correctable generation defect exists
and policy allows one repair, and ABSTAIN for an unsupported or contradicted material claim, an
unresolvable citation, missing evidence, persistent failure after repair, or provider/verifier
failure where safe verification cannot be established. Do not create unlimited regeneration loops.

A repair is capped at one attempt and constrained: supply the original EvidenceSet, the verification
failures, the supported and unsupported claim information and the grounding policy, and instruct the
generator to remove or correct unsupported content using only supplied evidence. Do not broaden
retrieval, search the web or inject pretrained facts. A repaired draft does not automatically pass:
run the entire verification flow again, and abstain rather than attempting a second repair.

Do not delete failed verification records and return the remainder as though nothing happened unless
that transformation is part of the controlled repair and the repaired answer is fully re-verified.
Auditability matters; preserve verification results in the request trace.

M8 may produce a typed final result containing approximately verification status, verified answer,
verified citations, claim verification results, provider and verifier traces, repair count, policy
fingerprints and EvidenceSet identity. Only PASS may produce a verified answer payload; ABSTAIN
returns a typed abstention. Only M8 may legitimately produce `verified = true`, and only after all
required checks pass; M7 drafts remain `verified = false` and M7 semantics must not be retroactively
mutated. Even so, do not implement the complete M9 Ask experience or enable the production Ask page;
M9 owns conversations, final QA UX, citations UI, the source-page viewer, highlighted regions,
conflict UI, abstention UI and streaming. Authorized development and inspection APIs and test views
are acceptable.

Verifier provider failure must fail closed — timeout, authentication failure, rate limit, malformed
structured response, unknown evidence id, empty response and network failure must never become PASS
and verification must never be silently skipped.

## Evaluation, testing and documentation

Extend evaluation with deliberately difficult claim-support cases: a fully supported answer, one
unsupported extra claim, a wrong numeric dose, a wrong unit, a negation reversal, overstated causal
language, a citation to the wrong block, an invented block id, support split across multiple blocks,
contradictory authoritative sources, a question-bank conflict, a table row/header mismatch, a
formula mismatch, a figure-dependent unsupported claim, a provider malformed response, a verifier
malformed response, a successful one-time repair and a failed repair leading to abstention. Reuse
frozen M5/M6/M7 fixtures where possible.

Keep evaluation layers separate and report claim-support accuracy, unsupported-claim detection,
contradiction detection, citation-id and citation-source correctness, false PASS rate, true
abstention rate, repair success rate and post-repair unsupported-claim rate. The most important
safety metric is an unsupported material answer incorrectly PASSed; track it explicitly and do not
optimize merely for a high answer rate. A wrong unsupported answer is unacceptable, abstention is
acceptable and a correct source-grounded answer is desired, so tune conservatively and never lower
verification requirements to increase coverage.

Normal CI must not require paid API calls: implement deterministic fake generators and verifiers,
structured failure cases and repair cases so claim verification is reproducible without network
access or secrets, with provider adapter contract tests kept separate. If `OPENAI_API_KEY` is
configured locally, run a small controlled live smoke over synthetic non-sensitive evidence,
recording only provider, model, success or failure, schema compliance, citation validity and
latency, never the key, and never claiming live verification falsely. Do not require an Anthropic
key merely because an adapter exists; an empty `ANTHROPIC_API_KEY` must not prevent startup, and
mock contract tests should still cover the adapter.

Preserve tenant isolation, corpus identity, EvidenceSet and draft ownership and source
authorization, revalidating server-side; a client must not submit another tenant's draft or
EvidenceBlock ids, and browser-provided provenance is not trusted. Add bounded tracing stages for
claim extraction, citation validation, claim verification, contradiction checking, repair
generation, repair verification and the final policy, preserving correlation ids and keeping keys,
sensitive queries, unbounded source text, prompts and raw provider responses out of logs.
Fingerprint and version the claim-extraction, verification, contradiction, repair and final policies
so a trace explains why an answer passed or abstained, avoiding hidden constants.

Follow the existing privacy architecture: create no migration unless a genuinely necessary
persistent entity is introduced, since request-scoped verification structures do not require one,
and justify any persistence in an ADR.

Extend only the authorized inspector as needed, exposing the M6 EvidenceSet, M7 sufficiency decision,
M7 grounded draft, M8 claims, M8 claim verification and the M8 final decision as clearly separated
stages, showing claim text, cited evidence ids, support verdict, contradiction status, repair
attempt and the final outcome, without fake medical confidence percentages and without activating
the final Ask UI.

Run focused M8 tests first, then affected regressions, using fresh-process backend partitioning
because this Windows environment has shown memory pressure with neural models and Docling in a
monolithic run, and ensure the groups exactly cover the collected backend tests without gaps or
overlap. Also run frontend tests, the production build, Playwright, ruff, formatting, mypy, skill
validation, Alembic verification, container health and the M1–M8 smokes, recording actual commands
and results without fabricating counts.

Create or update the M8 architecture documents and ADR covering claim extraction, the atomic claim
definition, deterministic citation validation, semantic support verification, contradiction
handling, verifier architecture, generator/verifier independence, the single repair attempt, the
final policy and the M8/M9 boundary. Create `docs/verification/m8.md` with the Git baseline,
architecture, files changed, claim and verification schemas, verifier provider and model,
deterministic and semantic checks, contradiction policy, repair behaviour, tests, evaluation cases,
false PASS results, unsupported-claim detection, citation verification, repair metrics, live
provider verification if performed, latency and limitations, stating clearly that synthetic
engineering tests are not clinical validation. Update `AI_HANDOFF.md` so another agent can resume.

## Stop condition

After M8 is implemented and independently verified, **stop**. Do not begin M9. Do not commit without
explicit authorization. If any acceptance criterion remains incomplete, report the exact blocker and
leave the repository in a safe recoverable state.
