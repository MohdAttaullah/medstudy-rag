# M11 — FULL END-TO-END EVALUATION + QUALITY FRAMEWORK

The milestone request as received, preserved in substance for cross-agent continuity in the same
way as [M1](m1.md) through [M10](m10.md) and the original [bootstrap](bootstrap.md) request. What
was actually built and measured is recorded in [the M11 report](../verification/m11.md); where the
two differ, the report is the truth.

---

Continue development of the existing Enterprise Medical RAG repository. M0–M10 are complete and
verified, and M10 must be committed as a clean checkpoint. M11 is an evaluation milestone: do not
redesign M0–M10, do not begin M12 production hardening, and do not add fashionable retrieval or
generation components merely to improve a metric.

The objective is a reproducible, layered, fail-closed evaluation framework that measures where the
system succeeds and fails from parsing through final abstention, while keeping synthetic
engineering evidence clearly separate from clinical validation.

## Layers and attribution

Evaluate parsing, chunking, embedding/index technical validation, retrieval, reranking, EvidenceSet
construction, evidence sufficiency, generation, citation correctness, claim verification,
abstention and conflict handling, and end-to-end Ask behaviour — each separately. Do not collapse
everything into a single "RAG accuracy" percentage. A failed answer must be attributable to the
stage that caused it.

Failure attribution is a core output. Carry forward the existing typed reason codes rather than
inventing duplicate names, and keep `FIRST_STAGE_MISS` distinct from reranker failure. End-to-end
failures should preserve upstream attribution rather than becoming a generic `FAILED`.

## Dataset governance and held-out cases

Inventory every existing evaluation dataset and classify it: implementation-adjacent/development,
frozen regression, held-out, expert-reviewed, synthetic, real-source-derived. The distinction must
be explicit in code and in reports. Cases created while implementing the feature they evaluate must
not be presented as independent evidence.

Create a deterministic, fingerprinted manifest recording dataset id, version, case ids, source
corpus, expected evidence, expected answerability, expected source authority, expected conflict
state, question and artifact category, provenance and review status. Results must identify exactly
which dataset version was used. Do not silently mutate gold labels; a correction creates a new
revision.

Introduce a meaningful held-out split, separating a development set from a held-out verification
set. If true independence cannot be achieved, state that limitation prominently. Do not claim
generalisation because implementation-adjacent fixtures score 100%.

Required case categories: ordinary factual, multi-hop, table-derived, formula-derived,
figure/image-dependent, question-bank, question-bank answer-key conflict, multiple authoritative
sources, contradictory authoritative sources, outdated source, no answer in corpus, ambiguous,
numeric/unit-sensitive, negation-sensitive, incomplete context, evidence-budget limitation,
provider failure, verification failure. Use existing fixtures where suitable and do not replace
historical datasets merely to produce cleaner scores.

## Per-layer requirements

Parsing: page/text/reading-order/bounding-box/table-cell fidelity, formula and figure artifact
preservation, OCR coverage, provenance completeness — remembering the documented Docling
cross-platform semantic-label variability, which must not be treated as deterministic ground truth.

Chunking: source-character and element coverage, deterministic boundary and hash reproducibility,
parent/child relationships, table row groups, repeated headers, formula atomicity, figure context,
question/option atomicity and explicit-answer preservation.

Embedding/index: model identity, revision, checksum, dimension, pooling, normalization, distance
metric, payload provenance, point identity, cross-environment comparison, ranking stability and
activation behaviour — measured separately from retrieval relevance, and never calling cosine or
dot scores medical confidence.

Retrieval: Recall@K, MRR, nDCG and precision reported independently for dense, BM25 and hybrid RRF,
broken down by useful categories, without overemphasising deep-K metrics on a corpus too small to
discriminate. Measure candidate-pool recall and `FIRST_STAGE_MISS` explicitly rather than blaming
M6 for a failure M5 caused.

Reranking: compare pre- and post-rerank ranking, measure MRR, nDCG and recall at the final anchor
K, and keep reranker regressions separate from first-stage misses. Raw CrossEncoder logits stay
diagnostic; do not derive confidence thresholds from them.

EvidenceSet: required source-element and character coverage, context noise, parent and sibling
contribution, table/formula/figure/question-bank completeness, deduplication, budget omissions and
provenance completeness — keeping known gaps visible rather than relabelling them away.

Sufficiency: expected decision agreement, false allow rate, false abstention rate, conflict
detection and reason-code accuracy. The most safety-critical metric is generation permitted where
evidence was insufficient or conflicting; track it explicitly and do not optimise for answer rate.

Generation: evaluated only where the gate legitimately permits generation. Structured-schema
validity, citation-ID validity, invented evidence ids, source-bound completeness, unsupported added
content, provider/model identity, latency, token usage and cost where available.

Verification: supported and unsupported claims, numeric and unit mismatch, negation reversal,
certainty and causal overstatement, wrong and invented citations, multi-block support, table header
and formula mismatch, source and question-bank authority conflict, figure-dependent claims, and
successful and failed repair. Track false PASS, false ABSTAIN, detection rates, citation
correctness and post-repair unsupported-claim rate. The most important metric is an unsupported
material answer incorrectly PASSed.

Abstention is a first-class safety behaviour: measure precision, recall, false allow, unnecessary
abstention, and conflict, no-evidence, verification-failure and visual-requirement abstentions.
Prefer safe abstention; do not tune to reduce the abstention rate.

Citations: separate deterministic identity from semantic correctness. A citation can be
structurally valid and semantically wrong; report both layers.

## Cross-cutting requirements

Measure the generator/verifier correlation limitation rather than merely mentioning it, comparing
against a different approved model only if one is actually available. Do not add a paid provider
integration to complete M11.

Include at least one outdated-source case preserving publication year, edition and authority, which
must not silently treat an outdated source as equivalent to a newer authoritative source. Evaluate
source-authority cases confirming that reranker score and retrieval rank do not choose truth and
that a question-bank answer is not automatically authoritative. Evaluate the existing abstention
behaviour for cases needing genuine visual interpretation; do not introduce a vision model.

Model bake-offs are optional experiments, not required features. No new component enters the
production path without measured failure analysis and an approving ADR.

Every result must record the effective configuration revision and the retrieval, reranking,
evidence, sufficiency, generation and verification policy and model fingerprints. Runs made under
different configurations must not be compared as though identical. Each run produces a manifest and
deterministic artifacts — per-case JSONL, aggregate JSON and a human-readable report — without
storing secrets.

Define quality gates only where the evidence justifies them, labelling each as a hard safety
invariant, an engineering regression threshold, an observational metric or uncalibrated. Do not
create arbitrary medical-quality thresholds from small synthetic datasets. If data are insufficient
for calibration, say so; do not tune on a held-out set and continue calling it held out.

Report stage-level latency with explicit timer semantics, distinguishing nested from additive
timers, and present no development-host number as a production SLO. Record environment
reproducibility, without requiring cross-environment floating-point bit identity where no layer
promises it.

Produce a per-case artifact suitable for future medical-expert review, exposing no private
chain-of-thought. State explicitly that M11 engineering evaluation is not clinical validation, and
never claim clinical validation, medical certification, perfect accuracy or guaranteed absence of
hallucination.

Do not optimise prompts to hide retrieval failures: report `FIRST_STAGE_MISS`, report
`CONTEXT_MISSING`, report verification failures, and do not weaken the verifier to increase the
answer rate.

Provide one documented entry point that fails clearly when prerequisites are missing, with a clear
offline/live distinction. Normal regression must work without API keys; live evaluation is opt-in
and must never be triggered silently. Include security regression gates proving cross-tenant
retrieval, foreign conversation and citation access remain impossible, readers cannot mutate
settings, provider keys are never exposed and unverified drafts are never displayed.

Continue the fresh-process backend test partition, verify it covers collected tests exactly, and
run frontend and browser regressions on a drained worker queue. M11 should not need a migration; if
no schema change is required, creating none is correct.

## Documentation and stop condition

Create or update `docs/evals/`, `docs/architecture/evaluation.md` and an ADR, documenting dataset
governance, evaluation layers, metrics, failure taxonomy, held-out policy, run manifests, quality
gates, live versus offline evaluation and the clinical-validation boundary. Create
`docs/verification/m11.md` with the Git baseline, datasets and versions, held-out methodology,
layers, metrics, failure counts, quality gates, offline and live results, latency, cost,
cross-environment findings, security regressions, backend and frontend tests, Playwright, Docker,
migration state and limitations. Update `AI_HANDOFF.md`.

After M11 is implemented and independently verified, **stop**. Do not begin M12. Do not commit
without explicit authorization. If any evaluation layer is incomplete, report it rather than
declaring M11 complete.
