## Purpose

The pipeline becomes: question → M5 hybrid retrieval → M6 CrossEncoder reranking → bounded
EvidenceSet → **Evidence Sufficiency Gate** → SUFFICIENT / INSUFFICIENT / CONFLICTING → generate a
grounded draft only when SUFFICIENT. The gate must execute **before** generation. The LLM is never
the source of medical truth; pretrained knowledge is not evidence; the indexed corpus remains
authoritative.

`INSUFFICIENT` produces a typed abstention rather than a medical answer. `CONFLICTING` must not
silently pick whichever source the reranker or the LLM prefers: return the policy-defined conflict
result or abstain, preserving all conflicting authoritative evidence for inspection.

## The gate

**Do not use one score as sufficiency.** No RRF, BM25, dense, CrossEncoder logit or weighted
combination may become a standalone medical-evidence threshold. M6's observation that CrossEncoder
logits separated the synthetic positives and negatives is an engineering observation, explicitly not
calibrated sufficiency, and must not become an M7 threshold.

Build a typed, inspectable sufficiency subsystem considering multiple evidence properties: coverage,
supporting block count, independent source count, source authority, question type, required evidence
type, source and context completeness, conflicting evidence, missing artifacts, retrieval failure
class, budget omissions and visual-source requirements. The decision must be explainable, returning
structured reason codes and evaluated signals rather than an opaque model judgment. Prefer
deterministic policy-driven logic unless an ADR approves otherwise.

The result contract carries approximately status, reason codes, evaluated signals, supporting and
conflicting evidence ids, missing requirements, policy version and fingerprint — using repository
naming conventions. Do not expose arbitrary percentages such as a medical confidence figure; M7
establishes no such semantics.

Requirements must be question-type aware: ordinary factual, table-dependent, formula-dependent,
figure/image-dependent, question-bank, multiple-source and conflicting-source cases. Use
deterministic classification or explicit structural signals; no uncontrolled LLM query rewriting or
speculative classification.

M6's measured table and figure context gaps must not be hidden. If a question needs table structure
the EvidenceSet does not contain, return INSUFFICIENT rather than letting the generator reconstruct
it. If answering genuinely requires interpreting an original figure and no approved vision path
exists, captions and structural labels are not equivalent — fail closed. Generated image
descriptions are not authoritative evidence.

Preserve the existing source-authority model. Question-bank answers and answer keys are assessment
material and do not automatically become medical ground truth; a high CrossEncoder rank does not
override authority. Preserve disagreement between assessment content and stronger reference
evidence, and between two strong sources.

Conflict awareness must be sufficient to prevent unsafe generation without becoming M8's
claim-level answer verification. M7 identifies material conflicts already represented in the
EvidenceSet; M8 later validates claims in a generated draft.

## Generation

Only once the gate returns SUFFICIENT, introduce the provider abstraction — `generate`,
`generate_structured`, and `analyze_image` only if consistent with the established architecture,
without silently introducing vision answering. Provider SDKs stay inside adapters; no vendor
specifics may leak into retrieval, sufficiency, domain, API orchestration or frontend code. Add
OpenAI and Anthropic adapters using the repository's configuration conventions. Do not architect
around one temporary frontier model; provider and model selection are configuration.

M7 is the first milestone where provider API keys are allowed. Keys are backend-only environment
variables; never create `VITE_`-prefixed copies, never hardcode, never commit. Keep `.env` ignored
and update `.env.example` with empty placeholders, then inspect Git for accidental secrets.

The generator may consume only the grounding policy, the user question, the EvidenceSet, the
approved evidence-block ids and the response schema. No arbitrary corpus access, no direct Qdrant
access, no provider-side retrieval, no provider web search, and no supplementing missing medical
facts from pretrained knowledge. The prompt must state explicitly that pretrained model knowledge is
not valid evidence.

Generation produces a structured grounded draft, not a final verified answer: draft content,
citation references, provider and model identity, generation trace, grounding policy identity and
EvidenceSet identity. Every citation must refer to an EvidenceBlock present in the supplied set; no
invented document, page, source or evidence ids; structurally invalid provider output is rejected.

Implement deterministic contract validation — do the referenced ids exist, are citations
syntactically valid, does the response satisfy the schema — but **not** M8's claim-level
support/entailment verification. M7 output remains a draft awaiting M8.

Provider timeout, authentication error, rate limit, malformed structured response, unknown citation
id, empty generation, unavailability and non-conforming schema all become typed failures. Never fall
back from grounded generation to an ungrounded answer, and never silently switch provider unless an
explicitly configured, auditable and traceable fallback policy exists.

Do not use the provider to alter M5 retrieval: no HyDE, multi-query, LLM query rewriting, automatic
synonym generation, GraphRAG, ColBERT or knowledge-graph retrieval.

M9 is the milestone for the complete user-facing Ask experience, so M7 must not expose unverified
drafts as final answers. An authorized inspection surface must label results as a grounded draft
awaiting verification, and must not activate the production Ask experience.

## Evaluation, testing and documentation

Extend the engineering evaluation fixtures to cover sufficient direct factual evidence, insufficient
or absent evidence, deliberate negatives, multiple supporting sources, question-bank-only evidence,
question bank conflicting with a stronger reference, conflicting authoritative sources, a table
requiring missing context, a figure requiring unavailable visual interpretation, formula evidence,
budget omission and a single incomplete fragment. Reuse the frozen M5/M6 fixtures where appropriate.
Keep synthetic engineering evaluation clearly separate from clinical validation.

Measure the gate separately from generation, reporting confusion-style outcomes and emphasising
false allows: unsupported generation allowed is substantially more serious than an unnecessary
abstention. Do not tune the gate to maximise answer rate; record abstentions honestly. Evaluate
grounded-draft behaviour separately — schema validity, citation-id validity, evidence-id
hallucination rate, generation only after SUFFICIENT, suppression on INSUFFICIENT and policy-
controlled behaviour on CONFLICTING, provider traceability and source-bound response behaviour —
without claiming answer correctness or entailment verification.

Provider contract tests must use deterministic mocks so ordinary CI needs no paid calls or secrets;
test both adapters. If valid keys are configured locally, perform a small controlled live smoke over
non-sensitive synthetic evidence and record provider, model, success, schema and citation validity
and latency, without recording secrets or full sensitive prompts. If no live verification is
possible, state that clearly and do not claim it.

Extend structured tracing with bounded stages, preserving correlation ids and keeping keys, secrets,
unbounded source text, private medical queries and full generated content out of metric labels.
Sufficiency and grounding policies must be typed and fingerprinted so a trace can reconstruct which
EvidenceSet, policy, decision, provider, model and grounding policy produced a draft.

Do not persist every question or provider response by default, and create no empty migration if no
durable entity is required. Preserve tenant and corpus authorization server-side; the browser must
not supply tenant identity or evidence ids belonging to another tenant, and provider adapters must
never become an authorization boundary. Verify no key reaches Git, the frontend, browser responses
or logs, and that the backend cannot be used as an arbitrary provider relay.

Run focused M7 tests, then affected regressions using the established fresh-process partition given
this host's demonstrated memory pressure, verifying the partition still covers the suite without
overlap or gaps. Also run frontend tests, the production build, browser tests, lint, format, mypy,
skill validation, Alembic verification, container health and the M1–M7 smokes, using actual
repository commands and without fabricating counts.

Create or update the M7 ADR and architecture documentation covering the gate, the three statuses,
reason codes, policy fingerprinting, the generation boundary, the provider abstraction, adapter
isolation, backend-only secrets, citation binding, failure behaviour and the M7/M8 responsibility
split; update README and CHANGELOG per project convention; create `docs/verification/m7.md` with the
exact Git baseline, scope, policy, signals, reason codes, provider contracts, models, security
checks, tests, evaluation dataset, sufficiency and generation results, any live provider results,
latency and known limitations, stating explicitly that an M7 grounded draft is not yet claim
verified; and update `AI_HANDOFF.md` so another agent can resume safely.

## Stop condition

After M7 is implemented and independently verified, **stop**. Do not begin M8. Do not commit without
explicit authorization. If any acceptance criterion remains incomplete, report the blocker rather
than declaring the milestone complete.
