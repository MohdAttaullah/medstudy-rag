## 6. Score Semantics

Very important:

Cross-encoder output score is a **ranking score**.

It is **not**:

- Medical confidence
- Probability the answer is correct
- Evidence sufficiency
- Clinical certainty

Do not expose it in UI as:

```text
Confidence: 92%
```

Do not apply sigmoid and call it confidence unless the model is explicitly calibrated for that purpose and independently validated.

Store/display it only as:

```text
reranker_score
```

for diagnostics.

---

## 7. Do Not Use RRF Score as Confidence

M5 measured that a negative query's top fused RRF score can exceed a weak positive query's score.

Therefore explicitly prohibit logic such as:

```python
if fused_score > X:
    evidence_is_sufficient = True
```

and similarly prohibit:

```python
if cross_encoder_score > X:
    answer_is_correct = True
```

M7 will implement an evidence-sufficiency policy using multiple calibrated signals.

M6 only ranks and constructs evidence.

## 11. Query/Candidate Length

Cross-encoders have finite sequence budgets.

Never silently truncate medical evidence.

Implement explicit policies.

Preferred priority:

1. Query remains intact.
2. Candidate must fit safely.
3. If candidate cannot fit:
   - Use its already structured M3 content.
   - Use deterministic safe sectional representation where possible.
   - Otherwise mark a validation/query finding.
4. Never silently chop the tail and pretend full evidence was reranked.

Record any truncation/representation policy explicitly.

Ideally default:

```text
silent_truncation = forbidden
```

## 17. Parent Context Expansion

M3 created parent/child relationships specifically for this stage.

After reranking, selected child evidence anchors may request their parent.

Example:

```text
Relevant child:
"Loop diuretics inhibit..."

Parent:
coherent subsection about mechanism / treatment.
```

Do **not** replace the precise child with the entire parent.

Preserve:

```text
anchor child
+
optional supporting parent context
```

The child remains the evidence anchor.

---

## 18. Parent Expansion Policy

Parent expansion must be conditional.

Do not automatically append every parent.

Use deterministic rules such as:

- Child lacks local explanatory context
- Parent within configured token budget
- Parent substantially overlaps anchor source
- Parent belongs to same `ChunkRun` / document

Avoid context bloat.

Configuration might include:

```text
context.parent.enabled
context.parent.max_tokens
context.parent.max_per_anchor
```

---

## 19. Neighbour Expansion

Support limited structural neighbour expansion.

For an anchor child:

```text
previous sibling
anchor
next sibling
```

may be useful when:

- Paragraph was deliberately split
- Definition continues
- Explanation spans adjacent chunks

Do not blindly fetch ±2 chunks around every hit.

Neighbour expansion must be:

- Same parent/logical structure where possible
- Same `ChunkRun`
- Sequence-aware
- Provenance-preserving
- Token-budget constrained
