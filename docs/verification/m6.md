# M6 verification report

Biomedical CrossEncoder reranking, deterministic context expansion, and a bounded
provenance-preserving EvidenceSet.

**What the EvidenceSet is.** A request-scoped, budget-bounded set of *source* blocks, each resolving
back to the original document. It is an inspection contract. It is **not** an answer, not a claim
that the evidence is sufficient, not a measure of medical certainty, and not a validated claim. No
generation, provider adapter, sufficiency gate or verifier exists. `READY` remains unreachable,
every document version stays database-constrained unsearchable, Ask is disabled, and every M5 and
M6 response carries `answering_enabled: false`.

**Every number below was measured over a synthetic corpus written for this repository.** It is not
licensed medical content, it has not been reviewed by a clinician, and none of it is evidence about
clinical performance. Where this report uses the phrase **synthetic engineering benchmark**, that is
the literal and complete claim being made.

## 2. Scope

Pinned MedCPT CrossEncoder reranking of the M5 fused pool; deterministic parent/neighbour and

and context-expansion baseline. M6 adds no relational entity, no migration and no ingestion state.

## 3. Provenance fixes

Two real provenance defects were found and fixed before this report. Both are corrections to M6
assembly, not new provenance systems: each reuses the existing M2/M3 tables (`Chunk`,
`ChunkSourceElement`, `DocumentElement`, `QuestionArtifact`) under the same tenant, chunk-run,
parse-run and document-version scope.

**Captionless figures were droppable.** `EvidenceAssembler` admitted a source only if it
contributed remaining text spans or table-row keys. An original figure whose chunk carries a
zero-length anchor span and no caption satisfied neither, so it was silently discarded — the one
case where the original artifact is the *entire* evidence. A `visual_only` predicate now admits it,
and deduplication keys it on `(document_version_id, artifact_id)` rather than on text. The figure's
`FIGURE_CAPTION` context reason is now emitted only when a caption span actually exists, so an
absent caption is no longer implied. The non-empty retrieval text such a chunk carries is the fixed
structural label M3 has written since 6cca864 (`backend/app/ingestion/chunking/builder.py:111`) —
not a generated description of the image. Nothing interprets the figure.

**Multi-chunk questions exposed only their anchor.** An atomic question that M3 split across
several chunks reported one `chunk_id`, so the other contributing chunks were unreachable from the
evidence. `EvidenceSource` and `EvidenceBlock` now carry `source_chunk_ids`; the repository
resolves every chunk sharing the question's `question_id` within the same tenant and chunk run, and
assembly propagates the full list. `QUESTION_EXPLANATION` is likewise emitted only when an
explanation exists.

Regression tests: `test_visual_only_original_remains_inspectable` and
`test_atomic_question_retains_all_contributing_chunk_ids`.

**Third gap, found during this verification.** The Evidence Inspector rendered a single
`Inspect chunk provenance` link built from `source_chunk_ids[0]`, which re-collapsed a multi-chunk
record to its anchor in the one place a reviewer would look. It now renders one link per
contributing chunk. Covered by
`links every contributing chunk of a multi-chunk source record`, and the live smoke now resolves
`/chunks/{id}/sources` for **every** id in `source_chunk_ids`, not just the first.

Every id, revision and checksum above was read back from the **live private runtime**
(`/health/reranker`), not from source. Loading is `local_files_only=True`, `trust_remote_code=False`
and `weights_only=True`; `num_labels == 1` and `max_position_embeddings == 512` are asserted after
load. A missing cache, a checksum mismatch, an overlength pair, a non-finite score or an HTTP
timeout each fails closed. **There is no automatic fallback to the M5 result.**

Ranking is by raw float32 logit descending, with ties broken by the original M5 fused rank and then
the chunk UUID — deterministic and independent of input order. The reranker persists neither the
query nor the source text; `input_hash` is a SHA-256 digest used only to prove the service scored
the pair the API sent.

**The CrossEncoder score is a ranking diagnostic.** It is not a probability, not medical
confidence, and not an evidence-sufficiency judgment. No sigmoid is applied and no threshold exists
anywhere in the code.

## 5. M5 semantics are unchanged

`git diff` over `core/retrieval_config.py`, `retrieval/`, `repositories/retrieval.py`,
`services/retrieval.py` and `models/retrieval.py` is **empty**. The Query Encoder, BM25 analyzer,
BM25 `k1`/`b`, the RRF equation, the RRF constant, both lane weights, the 40/40 lane budgets,
tenant/corpus alignment and `/retrieval/search` all behave exactly as in M5. Every change to a
shared file is strictly additive: four new settings fields, one new metric, one service attribute,
and one new route.

The M6 candidate pool is a **separately versioned** query-side policy — `retrieval-m6-pool-v1`,
default 20, maximum 40, five anchors — applied to a request-local copy of the M5 config. It never
mutates M5's own `final_top_k`.

## 6. Failure classification

Four classes are kept distinct, because they demand different responses:

| Class | Meaning |
|---|---|
| `FIRST_STAGE_MISS` | Relevant evidence never entered the M5 candidate pool. Reranking cannot recover it. |
| `RERANKER_REGRESSION` | Relevant evidence was in the top *k* before reranking and was pushed out of it. |
| `CONTEXT_MISSING_REQUIRED_SOURCE` | The anchor was found and ranked, but expansion did not include required surrounding source. |
| `CONTEXT_BUDGET_EXCEEDED` | An atomic unit could not fit and was omitted **whole**, with a recorded finding. |

`CORPUS_LACKS_EVIDENCE` is reported separately for queries with no relevant chunk at all, so a
correct negative is never counted as a retrieval or ranking failure.

## 7. Synthetic reranking evaluation

`scripts/evaluate_reranking.py` over a frozen first-stage snapshot
(`docs/evals/fixtures/m6-first-stage.json`, SHA-256 `eb19a7f80d65…`): 83 chunks, 24 gold queries
(22 positive, 2 negative). Freezing the M5 pool isolates reranking arithmetic from first-stage
variation. One M5 query-length boundary case stays rejected before reranking, as in M5.

| Pool | M5 MRR | M6 MRR | M5 nDCG@5 | M6 nDCG@5 | M5 R@3 | M6 R@3 | M6 P@5 | Pool recall | Inference mean |
|---|---|---|---|---|---|---|---|---|---|
| 10 | 1.0000 | 1.0000 | 0.9809 | **0.9967** | 0.9773 | **1.0000** | 0.3182 | 1.000 | 1104.7 ms |
| 20 | 1.0000 | 1.0000 | 0.9809 | **0.9967** | 0.9773 | **1.0000** | 0.3182 | 1.000 | 2138.4 ms |
| 30 | 1.0000 | 1.0000 | 0.9809 | 0.9959 | 0.9773 | 1.0000 | 0.3182 | 1.000 | 2901.7 ms |
| 40 | 1.0000 | 1.0000 | 0.9809 | 0.9959 | 0.9773 | 1.0000 | 0.3182 | 1.000 | 3928.7 ms |

Recall@1 is **0.7500 before and after**; reranking did not change which query gets the single best
chunk first. Recall@5/@10/@20 are 1.000 both before and after and are **structurally
uninformative** at 83 chunks. The only movement is at rank 3 and in nDCG@5.

**Candidate-pool comparison.** Pools 10 and 20 are identical on every measure. Pools 30 and 40 are
marginally *worse* at nDCG@5 (0.9959 vs 0.9967) and cost 1.4× and 1.8× the inference time of pool
20. Nothing here calibrates the default: pool recall is already 1.000 at pool 10, so this fixture
cannot distinguish the pools on the axis a larger pool exists to serve. **20 remains an
uncalibrated conservative default.**

**FIRST_STAGE_MISS: 0.** **RERANKER_REGRESSION: 0.** Across all 24 queries at all four pool sizes,
the only recorded class is `CORPUS_LACKS_EVIDENCE` ×2 — the two deliberate negatives, classified
correctly. No relevant item present in the M5 top five was displaced by reranking.

**A measured observation that must not become a threshold.** On this fixture the raw CrossEncoder
logit separates answerable from unanswerable queries where the RRF score did not:

| | positive min | negative max | separable |
|---|---|---|---|
| M5 fused RRF score | 0.031319 | 0.031746 | **no** |
| M6 CrossEncoder logit | 4.237551 | −14.252070 | yes |

This is an observation on 24 synthetic queries, not a calibration. It is recorded because it is
what the data shows, and because it is exactly the kind of result that invites an unjustified
cut-off. **No threshold was introduced.** Deciding whether evidence suffices is M7's problem and
requires evidence this benchmark cannot provide.

## 8. Context-expansion evaluation

Anchors are prescribed rather than retrieved, so this measures expansion alone. Ten cases over the
frozen M3 parse fixtures, at two sibling policies and four budgets.

| Policy | Source-element coverage | Source-character coverage | Noise ratio | Mean tokens | Parent rate | Neighbour rate |
|---|---|---|---|---|---|---|
| 0 prev / 0 next, budget 64 | 0.5333 | 0.4234 | 0.0000 | 16.6 | 0.00 | 0.00 |
| 0 prev / 0 next, budget 512 | 0.8833 | 0.8856 | 0.0333 | 131.1 | 0.10 | 0.00 |
| 0 prev / 0 next, budget 1024 | 0.8833 | 0.8856 | 0.0333 | 131.1 | 0.10 | 0.00 |
| 0 prev / 0 next, budget 4096 | 0.8833 | 0.8856 | 0.0333 | 131.1 | 0.10 | 0.00 |
| **1 prev / 1 next, budget 512** | **0.9333** | **0.8970** | **0.0333** | 132.0 | 0.10 | 0.10 |
| 1 prev / 1 next, budget 1024 | 0.9333 | 0.8970 | 0.0333 | 132.0 | 0.10 | 0.10 |
| 1 prev / 1 next, budget 4096 | 0.9333 | 0.8970 | 0.0333 | 132.0 | 0.10 | 0.10 |
| 1 prev / 1 next, budget 64 | 0.5333 | 0.4492 | 0.0000 | 19.8 | 0.00 | 0.10 |

One sibling each side raises source-element coverage 0.8833 → 0.9333 and character coverage
0.8856 → 0.8970 **at no measured increase in noise** (0.0333 in both) and at a cost of 0.9 tokens
per case. That supports the 1/1 default within the existing 256-token neighbour limit. The budget-64
rows show the budget class working as designed: coverage collapses to 0.5333 rather than admitting
a truncated fragment.

**Context gaps that remain, and are not hidden:**

| Case | Coverage | Character coverage | Class |
|---|---|---|---|
| `table` | 0.667 | 0.525 | `CONTEXT_MISSING_REQUIRED_SOURCE` |
| `figure` | 0.667 | 0.444 | `CONTEXT_MISSING_REQUIRED_SOURCE` |
| `paragraphs` | 1.000 | 1.000 | `CONTEXT_ADDED_NOISE` |

The `footnote` case fails at 0/0 and is **fixed** by the 1/1 policy — that gap is the measured
justification for the default, not a coincidence. The `table` and `figure` gaps persist at **every**
budget, so they are a policy limitation, not a budget limitation: the deterministic sibling and
parent rules do not reach all source the gold marks as required for those two artifact kinds. No
gold label was changed and no test was weakened to make them disappear. They are open work.

## 12. Backend regression — and an honest account of the crash

**The single monolithic full-suite run crashed.** `pytest backend/tests` as one process aborted at
15% with a **Windows fatal exception: access violation** inside Docling's PDF pipeline, with host
free memory at roughly 600 MB. That run produced **no passing full-suite result and none is
claimed**.

Verification strategy was changed rather than retried: run the suite as disjoint groups in fresh
processes, so each model runtime is released before the next group loads. The five groups
**exactly partition** the 468-test suite — no overlap, no gap — and every group ran after the
provenance fixes landed:

| Group | Files | Tests | Result |
|---|---|---|---|
| Base | config, eval fixtures, health, infrastructure, M1 units+integration, M2 units, M3 units+integration, probe | 178 | passed, 48.01 s |
| M2 integration (isolated, Docling) | `test_m2_integration.py` | 28 | passed, 217.49 s |
| M4 | units + integration | 71 | passed, 77.45 s |
| M5 | units + integration | 148 | passed, 112.60 s |
| M6 | units + integration | 43 | passed, 49.00 s |
| **Total** | | **468** | **468 passed** |

The M5 group is the one that was still running when the previous session ended; its log shows it
completed with 148 passed. It was not rerun because the log is complete and no backend source file
changed after it ran.

**The access violation was not reproduced as a deterministic test failure.** The 28 Docling
integration tests that the monolithic run crashed inside pass in a fresh process, and passed again
in the M2-isolated group. The evidence is consistent with memory pressure while several model
runtimes were simultaneously resident, but that is an inference from the circumstances, not a
diagnosis. It is recorded here because a native crash in a PDF parser is worth remembering, and
because "run the heavy suites in separate processes" is now the documented practice on this host.

## 17. Corpus consistency

Corpus identity is resolved once and rechecked three times within a request: after first-stage
retrieval and before hydration, after inference and before expansion, and again after expansion
hydration. Any change to the active index runs, sparse indexes or chunk runs mid-request raises
`CONTEXT_SOURCE_LINEAGE_MISMATCH` rather than returning a mixed EvidenceSet. Every source and
relative lookup reapplies tenant, chunk-run, parse-run and document-version scope; final assembly
works from the hydrated immutable snapshot and performs no further lookup.
`test_corpus_change_during_inference_fails_closed` and `test_tenant_and_run_scope_for_expansion`
cover this.

Deduplication is by chunk id, source interval within a document version, table artifact and row
identity, and figure artifact identity — all exact. **There is no semantic-similarity
deduplication.** Different documents, different versions and conflicting values are all preserved,
and the CrossEncoder score never decides which source is correct.

## 18. Known limitations

- **Synthetic engineering benchmark, not clinical validation.** 83 chunks, 24 queries, 10 context
  cases, no clinician annotation. It cannot establish medical reliability.
- Recall@5/@10/@20 = 1.000 at this corpus size is uninformative. The measured reranking gain is
  confined to rank 3 and nDCG@5; **Recall@1 did not move**.
- Pool recall is 1.000 at pool 10, so this fixture cannot calibrate the candidate pool. 20 is a
  conservative default, not a measured optimum.
- The `table` and `figure` context gaps persist at every budget and are open work.
- The raw CrossEncoder logit separates positives from negatives here. **This is not a threshold and
  must not be used as one.** Evidence sufficiency does not exist in M6.
- The EvidenceSet is bounded source material for inspection. It asserts nothing about answer
  correctness, sufficiency, certainty or claim validity.
- Reranking dominates latency and grows with the pool; the budget defaults are inspection limits,
  not a generation prompt budget.
- Timings are development-host measurements, not production SLOs.
- The combined single-process backend run remains untested on this host under memory pressure.
- **M7 has not started.**
