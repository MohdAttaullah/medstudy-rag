# M11 verification report

A layered, fail-closed evaluation framework measuring eleven stages of the pipeline separately,
with every dataset labelled by what it is actually allowed to prove.

**M11 engineering evaluation is not clinical validation.** Every dataset is synthetic, none is
expert-reviewed, no clinician saw any of it, and nothing below is evidence about clinical
performance. No claim is made of clinical validation, medical certification, guaranteed accuracy or
absence of hallucination.

**There is deliberately no overall accuracy score.** Parsing fidelity, Recall@5 and a false-PASS
count are not commensurable; one aggregate would move for reasons nobody could explain while
diluting the only quantity that must never move.

## 4. Held-out methodology, stated exactly

`m11-heldout-v1` is 25 end-to-end cases authored in M11 against the pipeline committed at
`e0ee0ad`. **Every policy they exercise was frozen before the cases existed**, so no case could
have influenced a threshold, a prompt or a bound. That is the entire claim.

It is not a held-out sample of any real population, it is synthetic, it was authored by the engineer
who ran it, and no clinician reviewed it. The dataset says so in its own notice.

**Two cases were revised after their first run, and what kind of revision matters.** One had wording
that shifted the conflict detector's four-word label window so the intended comparison never
happened; one named a deterministic reason code (`UNSUPPORTED_CLAIM`) where the system emits a
semantic one (`SEMANTICALLY_UNSUPPORTED`). Two `expected_layer` annotations were also corrected once
upstream attribution was understood. All four were errors in the *case*. **No policy, threshold,
bound or prompt was changed at any point in M11** — which is the line separating held-out discipline
from theatre.

## 5. Failure attribution

`taxonomy.py` maps every declared reason code to an owning layer using the repository's own codes.
Tests assert that every member of the real `ReasonCode` literals in `sufficiency/model.py` and
`verification/model.py` is classified, so neither M7 nor M8 can add a code that reports anonymously.

Attribution returns the **earliest** layer that declared a code. A retrieval miss reported alongside
an insufficiency is a retrieval failure the gate then handled correctly, not a gate failure.
`FIRST_STAGE_MISS` stays separate from `RERANKER_REGRESSION`; infrastructure codes stay separate
from evidence codes; correct refusals and success codes never inflate a failure count.

Held-out failure attribution: **19 cases carry an expected layer; agreement 1.000; zero unclassified
codes.** Attributed failures: SUFFICIENCY 10, VERIFICATION 6, EVIDENCE 2, GENERATION 1. The provider
outage is attributed to GENERATION and reported as `FAILED`, never as missing evidence; the
empty-corpus case is attributed to SUFFICIENCY and reported as `INSUFFICIENT_EVIDENCE`, never as a
technical failure.

## 17. End-to-end Ask

25 held-out cases: gate agreement **1.000**, outcome agreement **1.000**, layer attribution
agreement **1.000**, unknown reason codes **0**, repair cap respected.

Outcome distribution: VERIFIED 6, INSUFFICIENT_EVIDENCE 7, CONFLICTING_EVIDENCE 4, UNVERIFIED 7,
FAILED 1.

Five of the 25 cases attempted a repair — every case whose failure was of a repairable kind
(numeric mismatch, negation reversal, uncited claim, semantic rejection) plus the case written to
exercise a successful one. Exactly one repair per case, cap respected, and four of the five still
abstained afterwards: a repair is an opportunity to restate from the same evidence, not a second
chance to be believed.

The evaluator's outcome mapping is a copy of `AskService._outcome`; a unit test asserts the two
agree on every reachable state, so the evaluation cannot call a refusal something different from
what the product calls it.

**Conflict and authority.** Disagreeing guidelines, an outdated 2011 edition against a 2024 edition,
and an answer key contradicting the reference text all produce `CONFLICTING_EVIDENCE` with no
answer. The gold expectation is deliberately that the disagreement is *reported*, not that the newer
or higher-authority source is chosen: this repository has no reviewed basis for adjudicating a
fictional edition, and silently preferring one is the behaviour that must not happen. Reranker score
and retrieval rank never select truth, and a question-bank key is never automatically authoritative.

**Visual interpretation.** The figure case requiring genuine visual reading abstains with
`VISUAL_INTERPRETATION_UNAVAILABLE`. No vision model was introduced.

**One measured limitation, recorded rather than hidden.** `h-conflict-label-mismatch` documents that
the M7 conflict detector compares values only when the four-word label window preceding the number
matches between sources. Two sources stating different values for the same quantity in different
phrasing are not compared, the gate returns SUFFICIENT, and the abstention comes from M8 refusing the
draft instead. Attribution points at SUFFICIENCY, which is the useful reading: that is where it
should have been caught. The case is in the frozen dataset so the gap appears in every future report.

## 20. Offline and live

**Offline is the default and is what CI runs**: no API key, no provider call, no PostgreSQL, no
Qdrant. All seven hard safety invariants are measured in that mode. An integration test
monkeypatches `httpx.Client.send` and `httpx.AsyncClient.send` to raise on any request and asserts
the offline run still passes — so "makes no paid calls" is enforced, not asserted in prose.

Model-backed layers are skipped unless `--include-models` is passed. `--live` is never implied by
another flag and refuses without a configured generator.

**Live provider probe** (`--live`, openai `gpt-5.6-sol`): 5 cases, **3 real provider calls**, **2
suppressed by the gate before any provider was reached**. Schema valid, citations valid, **0 invented
citations**, gate agreement 1.000. Median latency **4121 ms**.

Three successful live calls demonstrate that the integration works. They establish nothing about
model reliability, and they are not clinical validation.

## 21. Latency and cost

Layer wall-clock this run: parsing 123.9 s, reranking 182.3 s, indexing 24.0 s, retrieval 22.7 s,
evidence 1.8 s, chunking 0.8 s, verification 0.22 s, end-to-end 0.04 s, security 0.03 s. CrossEncoder
inference is 1478 ms mean per query. Live generation median 4121 ms.

**Timer semantics:** layer timings are additive wall-clock around each layer runner. The stage
timings inside M5–M9 traces are nested — `pipeline_total_ms` contains `generation_ms`, which
contains `provider_ms` — and summing them double-counts. M9's report noted this confusion; it is
stated here explicitly rather than left to be rediscovered.

**None of these is a production SLO.** They are development-host measurements on Windows.

**Cost cannot be reported.** The M7 provider adapter does not read the `usage` block off the
provider response, so no token counts exist; reporting zero would read as "this was free."
Capturing usage is an M7 adapter change and was deliberately not made under an evaluation
milestone. It is the clearest piece of follow-up work M11 identified.

## 22. Generator/verifier correlation

**Not run, and recorded as not run.** The environment configures one approved model
(`gpt-5.6-sol`) for both roles, so `verifier_independent` is **false** on every run and is printed
on every report rather than mentioned once. With one model doing both jobs, an error the generator
makes is one the verifier is disposed to repeat, and that is the largest standing caveat on every
verification figure above.

M11 did not add a second paid provider integration to manufacture the comparison. The experiment
needs a second approved model to be configured; the harness records model identity per run, so it
can be run the day one exists.

## 28. Known limitations

* **Synthetic engineering verification is not clinical validation.** Nothing here measures medical
  quality, and no dataset is expert-reviewed.
* Seven of nine datasets are implementation-adjacent and prove intent, not generalisation.
* The held-out set is 25 synthetic cases authored and run by the same engineer. It is held out only
  in the sense that the policy was frozen first.
* The verifier is the same model as the generator; the independence experiment was not run.
* Cost is unreportable because the provider adapter captures no token usage.
* EvidenceSet coverage under the configured policy is 0.933, not 1.0.
* The M7 conflict detector misses disagreements phrased with different label windows; measured and
  recorded, not fixed under an evaluation milestone.
* Hybrid retrieval shows no Recall@5 advantage over dense on a five-document corpus. That is a
  property of the corpus, not a finding about hybrid retrieval.
* Latency figures are development-host measurements and are not SLOs.
* Security coverage here is contract-level; database-level tenant isolation lives in the M9/M10
  integration suites.

## 29. Boundary

M11 ends at measurement. **M12 was not started**: no production hardening, no deployment work, no
performance tuning. No new retrieval or generation component entered the production path — no
BGE-M3, ColBERT, GraphRAG, HyDE, query rewriting, additional provider or vision model. No prompt was
changed to let a model answer from pretrained knowledge when retrieval missed evidence, and no
verifier was weakened to raise the answer rate. Each of those would have improved a number while
making the system worse.

The M9/M10 safety chain is intact: an answer still reaches a reader only when the outcome is
VERIFIED, enforced by the response contract, the stored-turn view and two database CHECK
constraints, and the M9 and M10 suites pass unchanged at 64 and 48.
