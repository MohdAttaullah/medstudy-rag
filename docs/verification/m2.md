## 5. Tables, formulas, figures, OCR

* **Tables** keep a canonical cell list (text, 0-based row/column, spans, header flags), row/column
  and header-row counts, caption relation, bbox, page, markdown/HTML convenience renderings and a
  malformed flag. Multi-page continuation is *flagged* (`possible_continuation`,
  `continuation_of_id`, `table_group_id`, `continuation_evidence = adjacent_page_same_columns`) and
  never merged; uncertain pairs stay separate.
* **Formulas** keep the source expression exactly as parsed plus a whitespace-only normalization,
  notation, page, bbox and a link to an adjacent explanatory *paragraph* only. No model is asked to
  interpret or complete an expression.
* **Figures** keep page, bbox, media type, dimensions, byte size, the stored crop object and the
  parser-declared caption relation. No vision or language model is invoked.
* **OCR** defaults to `AUTO` (RapidOCR; only regions without a text layer). Per page,
  `source_text_chars` is measured from the PDF text layer with pypdf before OCR; a page with no
  text layer whose parse produced text is recorded `ocr_used` with
  `ocr_evidence = no_source_text_layer`, documented as a derived indicator. A suspicious OCR page
  is reported, and widespread suspicious OCR routes the document to review. Verified end to end on
  a fixture whose content exists only as pixels: `source_text_chars = 0`, `ocr_used = true`,
  `ocr_engine = rapidocr`, text recovered.

## 6. Validation

Document, page and artifact rules produce persisted `ParseValidationFinding` rows
(INFO/WARNING/ERROR/CRITICAL) and one structured result. CRITICAL → `FAIL` → job `FAILED`; any
ERROR or a page-count mismatch → `NEEDS_REVIEW` → job `NEEDS_REVIEW`; INFO/WARNING only →
`PASS_WITH_WARNINGS`; nothing at all → `PASS`. Both passing results reach `READY_FOR_CHUNKING`.
Thresholds are typed, frozen, snapshotted per run and included in the policy fingerprint. No rule
emits an accuracy percentage; findings carry codes, counts and page numbers, never document text.

## 9. Known limitations

* **Layout classification is not bit-identical across CPU/BLAS environments.** Between the Windows
  host and the Linux worker container, on the same parser version and the same bytes: page counts,
  page text, table cell contents, grid geometry and reading order were identical, but semantic
  labels on borderline regions were not — page header/footer classification, table caption
  association, formula detection and list grouping differed. The gold evaluation is therefore
  explicitly baselined per environment (host 9/9, container 4/9) and the automated test suite
  asserts our own persistence, provenance and authorization rather than a specific model judgement.
  This is a real property of ML layout parsing on borderline synthetic typography, not a defect
  that was worked around.
* Parse-quality thresholds are uncalibrated defaults chosen against synthetic fixtures. They are
  not validated against a real medical corpus.
* There is no review-approval workflow: a `NEEDS_REVIEW` document's operator path is reparse or
  cancel. Reparse consumes the job's bounded retry budget.
* No retention or cleanup of superseded parse runs and their artifacts.
* The parser runs inside the worker process with a document timeout, page guard and artifact size
  ceiling, but no hard memory sandbox and no per-tenant parse quota.
* Worker in-process parse metrics (duration histogram, per-code failure counters) are not exposed
  on a scrapeable endpoint; the scrapeable parse series are derived from PostgreSQL.
* Model weights download on first use; there is no offline or air-gapped mode and weights are not
  baked into the image.
* Page previews are rendered at a fixed scale with no per-page override, and preview failure is
  deliberately non-fatal.
* Fixtures are synthetic. Nothing here is clinical validation or compliance certification.
