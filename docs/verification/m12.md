# M12 verification report

Enterprise hardening: production identity, fail-closed configuration, tenant and source
authorization, secret containment, abuse ceilings, observability, recovery and operational
documentation.

**No claim of HIPAA compliance, HIPAA certification, production certification, clinical validation
or absence of hallucination is made anywhere in this report or in the system.** The controls below
are designed to support future compliance work. They do not constitute it.

**The safety pipeline is unchanged.** M12 added barriers around it and removed none. There is no
fast path, no verification-disabled mode, no provider-direct answering and no fallback to
pretrained knowledge; a test asserts the codebase contains no such switch.

## 3. Authentication

Production requires OIDC and is vendor-neutral: issuer, audience, JWKS URI and the claim names
carrying tenant and roles are all configuration. No code knows which provider is in use.

| Control | Behaviour |
|---|---|
| Signature verification | Unconditional; no flag exists to disable it, asserted by a test that reads the source |
| Algorithm selection | From configuration, never the token header — `alg: none` and RS256→HS256 downgrade both unreachable |
| Supported algorithms | Asymmetric only, so this service never holds a key that could mint tokens |
| Required claims | `exp`, `iat`, `iss`, `aud`, `sub` all verified |
| Tenant | From a verified claim; **missing is refused, never defaulted** |
| Roles | Unmapped role grants nothing; several mapped roles resolve to the **narrowest** |
| Rejection message | One opaque message, so a prober cannot learn which half of a forgery succeeded |
| JWKS | Cached, refetched on unknown `kid`, rate-limited against forced-refresh amplification |

**Development authentication has two independent barriers.** `Settings` refuses to construct a
production configuration whose mode is not `oidc` or which carries any development principal; and
`build_auth_provider` refuses again if handed one, covering a `Settings` built by a helper that
bypassed validation. Both are tested.

Production also refuses to start on nine other rules — rate limiting off, wildcard or HTTP CORS
origins, missing or development-default credentials, localhost backing services, non-offline
encoder models, and a configured provider without its key. Each names the setting and prints no
value.

## 4. RBAC

The `PERMISSIONS` inventory previously omitted `audit:read` and `settings:*` while routes enforced
them, so it was unusable for review. It is now complete, and a test scans the codebase and fails if
any route enforces a capability the inventory lacks.

| Role | Capabilities |
|---|---|
| `reader` | `document:read`, `ingestion:read`, `ask:submit`, `conversation:read` |
| `curator` | reader + upload/manage, all `ingestion:*`, `retrieval:search`, `generation:draft`, `generation:verify` |
| `admin` | curator + `settings:read`, `settings:write`, `audit:read`, `operations:read` |

Roles are explicit subsets. `curator` was previously "all of `PERMISSIONS`", so adding any
capability silently granted it. An unrecognised role now grants the empty set rather than raising
`KeyError` and surfacing as a 500.

`operations:read` is new and guards read-only operational state. The brief's `operations:admin` was
**not** created: operating the pipeline is the existing `ingestion:*` set, and a second name for one
authority is how two definitions drift apart.

## 5. Tenant and source security

**Isolation sweep.** `test_m12_integration.py` derives every parameterised GET from the OpenAPI
schema — **39 routes** — substitutes foreign identifiers, and asserts none returns 200 and all
require authentication. Deriving rather than listing means a route added later is swept
automatically; a hand-maintained list would leave the newest route, the one most likely to have the
bug, untested.

A foreign resource returns *not found*, not *forbidden*, so existence is not confirmed. Browser-
supplied `X-Tenant-ID` and `tenant_id` are ignored; a client-supplied `verified`, `answer` or
`tenant_id` on Ask is rejected with 422.

**Source authorization.** No presigned or reusable object-store URL is issued anywhere — `grep
generate_presigned` returns nothing, and there is no public bucket policy. Every source request
re-authorizes tenant, document *and* version and then streams the bytes. A verified citation is not
itself an authorization. Confirmed live: unauthenticated 401, owner 200, no `Location` redirect.

## 6. Secrets

`<NAME>_FILE` indirection resolves a mounted file into the variable before `Settings` is built.
Every managed store — Key Vault CSI, External Secrets, Vault Agent, Kubernetes and Docker secrets —
presents secrets as files, so this supports all of them and depends on none, and keeps the value out
of the process environment where `/proc/<pid>/environ` and crash dumps would expose it.

Only known names are resolved (resolving arbitrary `*_FILE` would turn a variable name into a file
read); a direct value wins so a local `.env` keeps working; an empty or unreadable file fails
startup naming the path, never the value.

**Leak checks.** Every endpoint's response is compared against the actual configured secrets —
database URL, S3 secret, both provider keys, every dev token. `/health/ready`, `/metrics`,
`/api/v1/settings`, `/api/v1/operations/status`, `/api/v1/documents` and the settings history all
clean, in tests and live. The frontend bundle contains no `VITE_OPENAI`/`VITE_ANTHROPIC`. Secrets
appear as presence booleans only.

## 7. Network architecture

Only the frontend and public API are externally reachable. **Health, readiness and metrics are
deliberately not proxied through the public origin** — they are internal surfaces for an
orchestrator and a scrape target, and the smoke asserts they are *not* reachable as JSON through the
browser origin. The CSP sets `connect-src 'self'`, so the page can reach no other origin; no
provider endpoint or object-store URL is ever handed to it. Compose binds PostgreSQL, Redis, Qdrant
and MinIO to `127.0.0.1`. Production refuses to start with a localhost backing-service URL.

## 8. Upload hardening

Content type and PDF magic bytes validated; size capped; filenames sanitized and never used as a
storage path (object keys are UUIDs, so traversal has no surface); page count and parse timeouts
bounded; failures isolate to the job and quarantine the document. Parsing runs in the worker, so a
pathological document cannot take the request path down. Upload is rate-limited per principal.

**There is no malware scanning.** Stated plainly rather than implied away.

## 9. Queue and worker reliability

M1's durable guarantees are unchanged and were not weakened: the transactional outbox, idempotent
delivery, durable job rows, bounded retries with `retry_count`, and quarantine for poison documents.
In-flight work is recovered from job rows rather than the queue, so an empty Redis after a restart
is correct. The M1 and M2 suites pass unchanged (179 and 28).

Job recovery and index rollback are documented in [backup and recovery](../architecture/backup-and-recovery.md):
vector semantics are never mutated in place, a new index run is verified before activation, and the
previous verified run stays active until then — so rollback is an activation change, not a repair.

## 10. Model provisioning

All three MedCPT models remain pinned by exact revision and SHA-256 and load offline.
**Production now refuses to start unless the embedding and query encoders have `offline=true`** —
previously the code default was `false` and only compose set it, so a deployment that forgot the
variable could silently fetch a different revision at query time. That was found by the preflight
script during this milestone. A checksum mismatch fails readiness rather than serving a different
vector space.

## 11. Provider failure behaviour

Every provider failure remains fail-closed and is reported as a technical failure, never as a
statement about the evidence. Verified live: with the provider raising,
Ask returns `outcome: FAILED`, `answer: null`, `verified: false`, no citations, no sources, and the
reason code preserved.

The load run surfaced four `GENERATION_SCHEMA_VIOLATION` outcomes on deliberately vague concurrent
questions — the provider returned output not matching the required schema, and M7 refused it. **No
pre-M12 baseline exists for that question set, so this is reported as observed, not attributed**;
the full live M5→M9 chain still reaches VERIFIED with a real grounded answer under the hardened
prompt, so the grounded path is intact. The important property held in every case: the failure was
`FAILED` with no answer, never an ungrounded one.

## 12. Observability

**Provider accounting** closes the gap M11 recorded. Real traffic during verification recorded
`provider_calls_total 6`, `provider_input_tokens_total 8118`, `provider_output_tokens_total 1610`
for `openai/gpt-5.6-sol`. Labels are provider and model only. Recording never raises, so telemetry
cannot fail a verified answer; a response without a usage block increments `provider_usage_absent_total`
rather than counting as zero. **No price is hardcoded** — `estimated_cost` returns None when no rate
table is supplied, because 0.0 would read as "this was free".

`ask_outcomes_total` per outcome, request counts and latency, ingestion and index metrics all
continue. Structured logs carry correlation id, event, status and duration, and no question, answer,
source text or key. Correlation ids propagate across API, worker and provider and survive
asynchronous ingestion — the property OTel instrumentation would build on; no exporter is wired and
no commercial vendor is required.

`GET /api/v1/operations/status` (`operations:read`) returns tenant-scoped job counts and retry
totals plus model identity, policy fingerprints, configuration revision and credential presence —
enough to attribute an answer to the exact model and policy that produced it.

Alertable conditions are documented as **suggested; none is deployed**.

## 13. Health versus readiness

`/health/live` touches no dependency — verified with a probe reporting PostgreSQL down. Pointing
liveness at readiness would make a database blip restart every replica of a healthy service.
`/health/ready` checks all four dependencies, returns 503 when any is unavailable, and **names the
unmet ones** in `unready`. Failure injection confirmed: a stubbed unavailable Qdrant gives 503 with
`unready: ["qdrant"]` while liveness stays 200.

`scripts/verify_restore.py` reported **7 of 7 checks passed**: schema head `m10_configuration`, all

## 16. Disaster recovery

Authoritative versus rebuildable data is enumerated in
[backup and recovery](../architecture/backup-and-recovery.md). Qdrant is **rebuilt, not restored**,
and that choice is recorded so nobody later assumes a backup exists. Recovery order: PostgreSQL →
object store → model cache → Qdrant → Redis (empty is correct) → API and worker. The system fails
closed throughout: a partially recovered index makes readiness fail rather than answering from a
partial corpus.

**No RPO or RTO is stated**, because none has been measured or approved.

## 17. Retention and deletion

Documented in [retention](../architecture/retention.md), including what is deliberately never
stored. Withdrawal removes a document from the active corpus; **it is a state change, not an
erasure**, and is not represented as a right-to-erasure implementation.

The complete deletion design is written out — object store, PostgreSQL, Qdrant points, BM25
postings, cached artifacts — together with the unresolved conflict at its centre: a verified answer
is bound by CHECK constraints to the citations it was verified against, so deleting a source while
keeping the answer leaves evidence-less verified text, and deleting the turn destroys user history.
Which is correct is a policy decision. **It is not implemented**, and writing it without that
decision would have produced a feature that deletes the wrong thing.

## 28. Known security risks

* **No malware scanning of uploads.** A PDF carrying an exploit for a downstream reader would be
  stored and served back to authorized users unchanged.
* **Rate limiting is per replica, not global.** N replicas allow N times each budget.
* **Base images pinned by tag, not digest.**
* **No token revocation check.** A stolen token is valid until it expires; lifetime and revocation
  are the identity provider's responsibility.
* **Audit tamper-evidence stops at the database boundary.** A superuser can drop the trigger; there
  is no cryptographic chaining or off-host log shipping.
* **`MEDRAG_ENVIRONMENT` can be set to `development` in a production deployment.** No system can
  distinguish that from an actual development environment; it must be set by the pipeline.
* **Prompt-injection defence at the prompt layer is probabilistic.** The structural guarantee — M8's
  deterministic checks — is what prevents an unsupported answer; an obeyed injection can at most
  cause an abstention.

## 29. Known operational limitations

* No backup scheduling; the procedure is documented and was exercised manually.
* No point-in-time recovery, no cross-region replication.
* No RPO or RTO — none measured or approved.
* No complete deletion workflow; the central policy conflict is undecided.
* No container resource limits in the shipped compose file.
* No CI configuration, Kubernetes manifests or Helm chart ship here.
* No OpenTelemetry exporter wired; no alerting deployed.
* Worker remains single-parse-per-pod; scale by adding workers, never by raising concurrency.
* Four `GENERATION_SCHEMA_VIOLATION` outcomes observed under concurrent vague questions, with no
  pre-M12 baseline for comparison.

## 30. Known quality limitations — unchanged from M11

Production hardening does not erase quality limitations, and none of these was hidden or restated
more favourably:

* **EvidenceSet coverage is 0.933 under the configured policy, not 1.0.**
* **The verifier is the same model as the generator**, so verification is not independent; the
  independence experiment remains un-run because only one approved model is configured.
* **The M7 conflict detector misses disagreements phrased with different label windows**, recorded
  in the held-out set as a documented gap.
* **Visual interpretation is unavailable**; figure questions needing it abstain.
* **Evaluation is synthetic-only and no dataset is expert-reviewed.**
* Provider latency is uncalibrated and no threshold anywhere is a measured production value.

## 31. Compliance boundary

**No claim of HIPAA compliance, HIPAA certification, clinical validation, production certification,
medical-grade accuracy or zero hallucination is made.** What exists is: security controls designed
to support future compliance work, auditability implemented, encryption-ready architecture, and

## 32. Final project boundary

M12 is the final planned milestone. **M13 was not created.** Remaining gaps are classified:

**Production blockers** (for a deployment with these requirements): malware scanning where uploads
are untrusted; a complete deletion workflow where right-to-erasure applies; global rate limiting
where a fleet is exposed to untrusted traffic.

**Known operational limitations:** everything in §29.

**Future enhancements:** digest-pinned images, OTel exporter, automated backup scheduling,
cryptographic erasure, off-host audit shipping, an independent verifier model.

**Clinical-validation requirements:** expert-reviewed datasets, clinician review of answers and
abstentions, and prospective evaluation — none of which is engineering work, and none of which this
repository can substitute for.
