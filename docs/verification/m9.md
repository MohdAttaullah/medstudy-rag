# M9 verification report

The complete Ask experience: verified answer delivery, citations, source navigation and
conversations.

**An answer reaches a reader only when M8 returned PASS.** The response contract makes any other
shape unconstructable, and two database CHECK constraints enforce the same rule underneath. M5–M8
responses are unchanged and still pin `answering_enabled: false`; no earlier endpoint became an
answering endpoint.

**Everything measured below used a synthetic corpus written for this repository.** No clinician
reviewed it, and none of it is evidence about clinical performance. Synthetic engineering
verification is not clinical validation.

## 3. Verified-answer-only enforcement

Four independent layers, so no single omission can leak a draft:

1. **The response contract.** `AskResponse` validates that an `answer` exists **iff** the outcome is
   `VERIFIED`, that `verified` agrees, and that a refusal carries no claims, citations or sources.
   The dangerous shape `{"outcome": "UNVERIFIED", "answer": "Take 50 mg…"}` raises at construction.
2. **The stored view.** `ConversationTurnView` enforces the same rule on read.
3. **The schema.** `ck_conversation_turns_answer_only_when_verified` and
   `ck_conversation_turns_verified_matches_outcome`. A direct SQL insert of an answer on an
   unverified turn is rejected by PostgreSQL — asserted by
   `test_the_database_refuses_an_answer_on_an_unverified_turn`.
4. **The absence of fields.** The public response has no `draft`, `sufficiency`, `verification`,
   `evidence_set`, `first_stage`, `reranked`, `prompt`, `provider` or `rationale`.

`AskConfig.requires_verified_pass` is `Literal[True]` and `stream_answer_tokens` is
`Literal[False]`; `test_no_configuration_can_relax_the_verified_requirement` asserts neither can be
set otherwise.

## 4. Outcomes and how they read

| Outcome | Heading shown | Distinguishing statement |
|---|---|---|
| `VERIFIED` | Answer | Checked against the sources cited with it |
| `INSUFFICIENT_EVIDENCE` | Insufficient evidence | Nothing filled in from the model's own knowledge |
| `CONFLICTING_EVIDENCE` | Sources disagree | Competing sources preserved; none chosen |
| `UNVERIFIED` | Could not verify an answer | Evidence existed; the draft is not shown |
| `FAILED` | The answering service failed | A technical failure, explicitly not about the evidence |

No confidence figure exists anywhere; `test_no_confidence_number_exists_anywhere_in_the_contract`
and a frontend test assert it.

## 5. Enablement transition

M5, M6, M7 and M8 responses keep `answering_enabled: Literal[False]` and are otherwise untouched;
`test_earlier_milestone_responses_still_refuse_to_answer` asserts all four by type, and an
integration test re-checks two of them live. `AskResponse` pins `Literal[True]` as a statement about
that one contract. There is no global boolean that turns answering on.

## 6. Authorization

`reader` gains `ask:submit` and `conversation:read` only. Inspector scopes stay separate:
`test_a_reader_may_ask_but_never_sees_the_inspector` asserts a reader gets 200 on `/ask` and 403 on
`/retrieval/search`, `/retrieval/draft` and `/retrieval/answer`.

Conversation ownership comes from the authenticated principal. Another tenant's id returns 404 —
indistinguishable from an id that never existed, so probing reveals nothing. Ownership is checked
**before** the pipeline runs: `test_continuing_an_unknown_conversation_fails_closed` asserts zero
provider calls for a foreign id.

## 7. Persistence and migration

`m9_conversations`, revising `m5_hybrid_retrieval`. Three tenant-scoped tables with composite keys.
`alembic check` reports no drift; the round trip `head → m5_hybrid_retrieval → head` was executed and
the integration harness downgrades to base and back on every run.

Stored: question, outcome, answer (only when verified), declared reason codes, model identity,
timings, citation identifiers and the exact cited text. **Not stored**: prompts, provider responses,
failed drafts, verifier reasoning, EvidenceSets.

Citation text is stored rather than re-resolved, because the answer was verified against those exact
words and a later re-parse must not silently change what a stored answer appears to cite.

The downgrade refuses while conversations exist. That is deliberate: every other table can be
rebuilt from its source document, and a user's question history cannot.
`MEDRAG_ALLOW_CONVERSATION_LOSS=1` acknowledges the loss, which is what the test harness sets on the
throwaway schema it just created.

## 8. Citations and source navigation

No new document routes. Citations deep-link into the M2 parse inspector, which already streams page
previews, elements, tables, figures and formulas under `document:read` with tenant scope resolved
server-side, so the browser never holds an object-store URL.

The link targets the page the cited **span** is on, not the citation's first page — a citation
spanning two pages whose region sits on the second must open the second. Regions come from M2
provenance: shown when recorded (`Region on page 3: 10.0, 20.0, 30.0, 40.0`) and stated as absent
when not (`No region recorded for this source; the page is shown instead`). No geometry is invented.

Table citations show canonical row and header identity; formula citations state the notation is the
document's own and is not rewritten; figure citations distinguish an available original crop from an
unavailable one. Assessment sources carry an explicit note that a recorded examiner answer is not,
by itself, a medical reference. The source list is built only from citations that supported the
answer; retrieval candidates that supported nothing stay in the inspector.

## 11. Defects found and fixed during M9

**Relaxing service-level authorization opened `/retrieval/search` to readers.** The shared retrieval,
drafting and verification stages had to accept a reader's `ask:submit`, and `/retrieval/search` had
no route-level check of its own — it relied entirely on the service. My own test caught it; the route
now enforces the scope its module docstring already claimed. Defence in depth requires both depths.

**An unknown conversation id was only detected after a provider call.** Ownership was resolved during
the commit, after generation and verification had already run. It is now checked before the pipeline
starts, so a foreign id costs nothing.

**A citation opened the wrong page.** The link used the citation's first page rather than the page
its span is on, so a multi-page citation would open a page the highlight is not on.

**Three obsolete assertions.** `App.test.tsx`, `workspace.spec.ts` and `retrieval.spec.ts` asserted
that answering was unavailable — the thing M9 exists to change. Each was rewritten to the narrower
invariant that still holds (access is gated; no answer appears before one is asked) rather than
deleted.

**A crude key check.** `test_no_provider_key_reaches_the_frontend_bundle` scanned for the substring
`sk-`, which the new `ask-outcome` element id contains. It now matches a key shape.

## 12. Known limitations

- **Synthetic engineering verification, not clinical validation.** Nothing here says anything about
  clinical accuracy.
- **The verifier is the same model as the generator** (`MEDRAG_VERIFIER__*` unset), so a shared blind
  spot can pass both stages. Recorded on every turn as `verifier_independent: false`.
- **Coverage is low.** Most questions against the ingested parsing fixtures abstain, because those
  fixtures are shaped to exercise the parser and their text is fragmentary. The live pass required a
  purpose-written coherent document.
- **Latency is dominated by the provider** — roughly 13.7 s end to end, almost all generation and
  verification. Not a production SLO.
- Streaming carries progress stages only; answer text is delivered atomically. Deliberate.
- Region highlighting depends on M2 recording a bounding box; where none exists the page opens
  without one, which is stated rather than approximated.
- Conversations are per-user within a tenant; there is no sharing, export, deletion or retention
  policy yet.
- Idempotency is per submission key. A client that omits one gets a fresh key per submission.
- **M10 has not started.**
