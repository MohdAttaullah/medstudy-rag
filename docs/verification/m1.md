## Implementation

The control plane provides authorized PDF upload, strict publication/source/authority metadata,
immutable versioned originals, streamed SHA-256, tenant-scoped duplicates, durable idempotency and
failure compensation. PostgreSQL owns job state, ordered append-only history, audit and the
transactional outbox. Celery confirms receipt without advancing beyond QUEUED. Retry/cancel/archive
are permission- and state-checked; late or duplicate deliveries cannot revive cancelled work.

AuthProvider has a clearly marked development bearer adapter. The server derives actor, tenant and
reader/curator/admin role; payload identity is never trusted. Private source downloads verify tenant
and document/version membership. The browser stores its credential in tab memory only.

Originals use UUID S3 keys and pinned object version IDs. UploadIntent is committed before storage;
document/version/job/history/outbox are finalized together. Ambiguous commits are resolved before
compensation. Failed cleanup is durable and reconciled; committed originals are preserved.
The job snapshots its ingestion settings. Every version remains unsearchable.

UI: Library supports PDF selection/drop, shared metadata, actual transfer progress, errors,
duplicates, document lists and archive. Details show publication metadata/editing, versions, source
download, checksum/size, jobs and ordered history. Operations shows real jobs, state/history/errors,
receipt and authorized retry/cancel. Replayed uploads display their current status; confirmed
failures obtain new request keys while network retries preserve the original key. Ask stays disabled.

Uploads use raw PDF bodies, UUID Idempotency-Key and base64 UTF-8 JSON X-Upload-Metadata.
List limit is at most 100. Document filters include source, subject, specialty and archival state.
Jobs filter by status, document, since and active state. Errors return a safe code/message/details
with correlation; request validation omits sensitive input.
