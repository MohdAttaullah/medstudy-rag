# Parsing extraction-fidelity evaluation

This measures one narrow question: **did the parser recover the structure a human can see in the
source document?** It is not RAG evaluation. There is no retrieval, no generated answer, no judge
model and no notion of medical correctness anywhere in it. A document can score perfectly here and
still be useless as evidence; keeping the two questions apart is the point.

Retrieval and answer evaluation remain unimplemented — see
[retrieval evaluation](retrieval-evaluation.md) and [answer evaluation](answer-evaluation.md).

## Dataset

`docs/evals/parsing-gold.json` (schema `medrag.parse.gold/1`) over the synthetic corpus in
`backend/tests/fixtures/parsing`, generated by `scripts/create_parse_fixtures.py`. Every fixture is
original synthetic content written for this repository: no copyrighted textbook, question bank or
guideline text, and no wording intended to be medically meaningful.

| Case | What it exercises |
|---|---|
| basic-text | Headings and body paragraphs |
| multi-page | Page boundaries, repeated running head and foot, per-page markers |
| table | 4×4 grid with a header row and a caption below it |
| continued-table | A table split across a page break, which must not be merged |
| figure | Raster diagram, extracted crop, caption relation |
| formula | A displayed equation set as a fraction with an equation number |
| two-column | Column-wise reading order rather than row-wise |
| question-bank | Numbered stem, A–D options, `Answer:` and `Explanation:` cues |
| scanned-like | A rasterized page with no text layer, recovered only by OCR |

Each case declares expected page count, exact or minimum element-type counts, table/figure/formula
counts, table grid dimensions and cell counts, caption relation counts, OCR page count, required
text fragments and fragments that must appear in a given reading order. The evaluator additionally
checks that page numbers are the contiguous 1-based printed sequence, that reading order is
contiguous, and that no element carries a malformed bounding box.

## Running it

```powershell
uv run --extra parsing python scripts/evaluate_parsing.py
```

It prints the parser version, the policy version and fingerprint, per-case and per-check counts,
and every failure. It exits non-zero on any failure, so a parser upgrade or configuration change
that quietly degrades extraction is visible instead of absorbed.

## Environment baselining

Layout classification is **not** bit-identical across CPU/BLAS environments. Measured between the
Windows host and the Linux worker container on the same machine and the same parser version:

* Stable: page counts, page text, cell contents, table grid geometry, reading order.
* Not stable: semantic labels on borderline regions — page header/footer classification, caption
  association, formula detection, list grouping.

The dataset therefore records `baseline_environment` and is re-baselined per environment rather
than relaxed into vagueness. A changed count is a signal to review a real difference, never a
reason to widen the expectation.

This is also why the automated test suite does not assert those labels: `backend/tests/
test_m2_integration.py` asserts our own persistence, provenance, artifacts, authorization and
failure behaviour, and uses a fixed parser output where a specific parser judgement is needed.

## What this does not establish

Nothing here is clinical validation. Synthetic fixtures do not represent real medical typography,
scan quality, multi-column reference layouts or malformed publisher PDFs. There is no accuracy
percentage, and none should be quoted from this harness. Threshold defaults in `ParseThresholds`
were chosen against these fixtures and need re-tuning against a real corpus before any claim about
production parse quality.
